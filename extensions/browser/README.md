# Browser

## Backend and protocol

The browser runs on the Halo server machine, behind the Halo private extension socket, never a public debugging port. It accepts only proxy-validated `X-Halo-Caller` context; production authentication/entitlement, same-origin checks and header stripping belong to Halo hook 1. The protocol is `backend/src/protocol.ts`; generic hook types are a byte-for-byte, SHA-256-pinned development snapshot under `contracts/halo-core/`. Regenerate after coordinated core changes, never edit copies by hand:

```sh
node extensions/browser/scripts/check-core-contract.mjs --source "$HALO_SOURCE_ROOT" --check
```

Routes: `GET /status`, session-only `POST /command`, Admin-only `POST /view` and `GET /stream?viewId=…` WebSocket, bound `GET /operations/:id`, and owner-only `GET /artifacts/:id` for requested PNG screenshots. State, runtime, operation and error messages use the frozen nested envelopes. Viewer subscribes with protocol 1 and acknowledges binary `uint32-be sequence || JPEG` frames **after decode**. Context comes from the host/proxy, not the command body. Screenshots are private, bounded and expire; never expose profile paths or arbitrary files.

One persistent profile per canonical workspace hash, one owner session. Other sessions get `busy`; different workspaces do not share cookies. Multiple viewers are read-only except the single input owner. Handoff fences queued agent actions and immediately returns `waiting-for-user`, but the owner's `read`, `tabs`, `screenshot` (including artifact/result retrieval) and runtime `status` remain available without taking input control. Page reads collect nonempty current password values in one batch per frame, including nested iframes and open shadow roots, both before and after reading page data. If the value sets differ or a still-attached frame cannot be sampled, the read returns `operation-failed` without retry or browser teardown; detached frames are skipped during collection. Redaction uses `••••` only in content fields: text, ARIA, title, URL and ref names. Text/ARIA/ref-name variants cover collected raw values, Playwright 1.61.1 `normalizeWhiteSpace` (remove U+200B/U+00AD, trim, collapse whitespace), zero-width removal with and without normalization, title normalization, URL parsing's ASCII tab/newline removal, and JSON/YAML-escaped spellings, longest-first. Title normalization maps C0/C1/DEL to spaces, removes U+200B–U+200D/U+FEFF/U+2060/U+00AD, collapses whitespace and trims; both title and password variants are normalized before replacement, then the title is capped at 200 characters. URL matching uses `new URL()` and compares both raw and decoded spellings. A non-throwing lenient decoder decodes valid `%XX` UTF-8 characters (either case of percent hex), retaining malformed percent syntax and invalid UTF-8 bytes while still decoding valid characters beside them. Each pathname segment/hash and each password variant receives the same decoding; raw query keys/values and password variants both replace `+` with a space before lenient decoding. Matching retains raw-component/raw-password and decoded-component/raw-password checks as well, including values encoded by `URLSearchParams`. Title normalization is applied to matching spellings; any match replaces the whole component before URL serialization, preserving unrelated component spellings, query order and duplicate entries. Userinfo is already removed; an unparseable URL becomes `about:blank`. URL encodings are not enumerated as text variants. Empty variants are discarded; there is no minimum password length. All `[ref=…]` syntax is stripped from ARIA before redaction (including the same syntax inside values); matching value variants cover that removal too. Redaction precedes truncation and never changes live forms or protocol IDs (`tabId`, `snapshotId`, ref IDs/roles). Short passwords may over-mask ordinary content, but returned `snapshotId:rN` targets remain actionable.

For sampled values, the guarantee covers spellings produced by read rendering itself, browser URL serialization and title normalization as described above, not arbitrary page-script truncation, encoding, concatenation or other transformations. This remains sampled value redaction, not an atomic DOM snapshot. It can miss A→B→A value changes, empty→value→empty between samples, and a frame mounted and removed entirely between samples; these windows are accepted, not retried or otherwise detected. Closed shadow roots cannot be sampled; Playwright 1.61.1's ARIA snapshot also does not enter them (covered with real Chromium), so passwords confined there are absent from both. A page that copies an unknown closed-root value into ordinary visible text is outside this guarantee. Screenshots retain native password rendering rather than this read-output redaction.

There is no explicit resume command. An action checks the current human marker before executing: any new message in this same chat permits automatic return to agent control, immediately clearing the input owner, advancing the control epoch and switching to 2 FPS. Release-all is enqueued behind already-in-flight viewer input in the same serial queue; agent execution (including sign-in commands) awaits that release, so delayed key-up cannot race the next action. If release fails and the captured target page reports `isClosed()`, its input dispatcher is discarded and the barrier resolves; error text alone never proves closure. Other release failures mark the workspace unavailable and stop it without overwriting the last checkpoint; the current command returns `unavailable`. A new-ID `open` waits for removal to finish before reusing the profile. Forced teardown retains the old context and its first close promise, waiting up to 3 seconds for a context close event rather than treating kill/taskkill dispatch as exit; graceful close also awaits Playwright's full close promise. On timeout the workspace remains stopping/unavailable and blocks relaunch; a later command can retry the bounded wait and recreate it only after exit. A sign-in command rechecks owner/driver/epoch after the wait and returns `waiting-for-user` before starting the service if control changed. The takeover's current marker, a stale marker, or pending import/commit/close prevents automatic return; approval alone is not a new human message. Reading leaves the driver and takeover fence unchanged, even after a new message. Agent handoff and manual takeover still prevent already-started same-turn actions from reclaiming control.

A Settings-opened viewer may take control before any agent owns the browser. The first agent request claims ownership; reads run immediately and an action with a human marker may reclaim control in that same turn (`fence = null`). UUID markers cannot determine whether that turn began before the ownerless takeover: allowing that first action is an accepted trade-off, rather than requiring a second user message. Until claimed, closing the last viewer releases control to idle, and five minutes without input expires the lease even while visible. Claimed unattended handoffs retain the thirty-minute lease; running work and initialization cannot expire through the idle timer.

At 1280×800 / JPEG 70, delivery is time-capped at 2 FPS for agent/watch and 10 FPS for user input, with one retained latest frame and one outstanding frame per viewer; mode transitions preserve last-send timestamps. No viewers suspends CDP capture. This reduces traffic, **not native Chromium encoding cost** on animated pages.

Requested PNGs run in the workspace command lock, outside this delivery limiter. Chromium 149.0.7827.55's `PageHandler::ScreenshotCaptured` reports `Unable to capture screenshot` only for an empty snapshot (encoding has a different error); its surface-copy path already retries internally. For that exact Playwright/CDP error only, the backend brings the same page to front, confirms visible state through two animation frames, rechecks the command fence and retries once within the original 10-second screenshot budget. Both captures and every awaited recovery step (`bringToFront`, visible-paint wait and handle disposal) race the same monotonic deadline; a hung recovery call fails with `operation-failed` and releases the command lock. Late capture/recovery completions cannot continue the operation, write an artifact or overwrite its terminal result. Handle disposal runs after capture, is bounded by the remaining time and is best-effort: its failure/timeout cannot replace the capture result. Other errors, failed visibility checks and a second capture failure are not retried. The regression assertion reports HTTP status/public error code before reading `artifactId`, never a raw exception.

Investigation with manufactured pages: ordinary headless 200 captures and background-tab 200, persistent dual-context 300, and persistent start/stop-screencast 200 all completed without this error. The reported failure occurred without a viewer, excluding the viewer limiter/screencast transition in that case. These runs plus Chromium source identify the empty-snapshot class, **not the exact intermittent trigger** (first surface, visibility and process load remain unproven); the single retry is narrow recovery, not a claim that Chromium's underlying race is fixed.

Data lives in `$HALO_EXT_DATA_DIR/workspaces/<sha256>/`: dedicated `profile/`, atomic session-cookie journal, tabs and ephemeral artifacts. Session partition site and ancestor bit survive restore before navigation; logout writes an empty journal and unchanged state skips writes. Checkpoints debounce meaningful input/navigation/cookie-response events until interaction settles and run after agent mutations and on orderly close. Background Set-Cookie login/logout responses mark dirty without retaining header values. Pointer movement and release events never mark dirty or cause periodic cookie scans. Quiet script cookie changes and changes not yet checkpointed can be lost on abrupt crash. Unexpected context/browser exit invalidates runtime, cancels work and disconnects viewers; the next `open` starts a fresh context from the last durable checkpoint rather than keeping a stale live context. Unix directories/files use private modes. Windows creates current-user inheritable ACLs with `whoami`/`icacls`. Forced Windows cleanup starts detached, unreferenced `taskkill /PID <pid> /T /F` without waiting for that helper process, including in the backend exit handler; the cleanup child can finish after backend exit. Live profile replacement still waits for the old browser context to close as above; backend shutdown retains its separate 3-second budget and cannot reopen profiles. Removing each owned PID before dispatch prevents repeated context/global/exit cleanup from spawning it again; spawn errors are best-effort and ignored. POSIX retains direct process-group SIGKILL. ACL behavior and actual Windows tree cleanup still need native hardware acceptance.

Desktop target preference is installed stable Chrome, then Edge, then pinned Playwright Chromium; Linux uses pinned Chromium in extension-data. On Linux, Chromium's runtime configuration and cache are also in extension-data: `chromium-xdg/{config,cache,data,home}` supplies its child-only XDG config/cache/data and HOME. Crashpad uses the config directory; NSS uses `data/pki/nssdb` instead of the real user's `~/.local/share` or legacy `~/.pki/nssdb`. The backend's HOME/environment stays unchanged for sign-in source discovery, and macOS/Windows launch environments are unchanged. Linux does not inherit the real user's NSS certificate database; no HOME write permission is added to Halo's sandbox. Target profiles never point to ordinary browser profiles. Installer uses Playwright's locking/atomic completion and inherited proxy variables, with a bounded download; its persistent runtime registry is `browsers/` in extension-data via `PLAYWRIGHT_BROWSERS_PATH`. Download ZIPs and Playwright's temporary launch artifacts use TMPDIR (Halo's private writable `/tmp`), not the real HOME. Backend ready IPC precedes all downloads and launch.

Launch errors expose only fixed categories (`missing-libraries`, `crashed`, `timeout`, `exited`, `unknown`) and write one `[Browser]` summary to backend stderr, never raw Playwright stderr, profile paths or environment values to the UI/agent. Only a recognized shared-library loader or Playwright host-dependency failure recommends installing libraries; other failures say “Browser failed to start” with the category. Missing system libraries require administrator action outside the extension, not an automatic privileged install.

Sign-in is supplied by `createSigninService(host)` in `backend/src/signin-import/index.ts`. `signin-service.ts` is the stable D→F port: service `sources`, `import`, `dispose`; host `caller`, `signal`, `withCommit`, and IPC `confirm`. `withCommit` holds one original context for apply through checkpoint or rollback plus undo checkpoint, exposing request-checked `withContext` and abort-independent `cleanup`/`checkpoint`. Missing/replaced/closing contexts reject; cleanup never relaunches. Consent waits never hold this lock. Background checkpoints/input queue behind the commit, and takeover is refused during it. Live workspace close requests cancellation, waits for undo, and invalidates the guard after a bounded 30-second cleanup wait. All self-expiry paths (including commit/initialization deadlines) use backend removal, allowing the next new-ID `open` to create a fresh workspace context. Process stop uses a separate 3-second workspace teardown budget, shortening an in-progress live close too, plus at most 250 ms to settle operation DTOs before closing IPC/sockets. The real entry retains its 4-second forced exit, inside Halo's unchanged 5-second SIGTERM→SIGKILL window. Forced teardown reports uncertain, not clean cancellation; abrupt hard kill cannot guarantee undo or notification delivery. Late abort cannot overwrite an already committed imported result. The production entry wires that factory directly; no source-discovery stub is installed. A cancelled/unavailable import can be explicitly retried with a new request ID after a newer human message permits automatic control return. Pending and successful imports stay deduplicated by normalized `(host, exact, source)` scope, including equivalent URL/case/path spellings and a repeated successful request in a later turn. A successful import records its returned source ID as an operation alias, so implicit success followed by a new-turn explicit request for that ID does not create a second service/import. The alias inherits the operation's lifetime; other sources remain separate. Transport retries with the same ID never re-run the operation, and changing that ID's original request remains invalid.

### Sign-in platform prerequisites

- **macOS:** `privacy` means an EPERM/EACCES reading or enumerating browser data, usually macOS privacy protection rather than proof of TCC specifically or a reason to close Chrome. In System Settings → Privacy & Security → Full Disk Access, add **Halo.app from Applications** for desktop; if launched from a terminal, grant the **terminal app** instead. TCC attributes access to the responsible process. Ensure the switch is on, then completely quit Halo (**Cmd+Q**) and reopen it: permission changes may only take effect after Halo is fully quit and reopened. Halo uses an ad-hoc signature; after an upgrade, if access fails again, toggling the entry off/on or removing and re-adding it **may** be necessary. This is not a guaranteed explanation for every delayed permission change. During import, allow the Keychain request for the browser's “Safe Storage” item; `keychain` specifically asks to retry and click Allow (or Always Allow) after an OS-reported denial/cancellation. Missing keys and other tool failures retain the generic `key` reason.
- **Windows:** `locked` on EBUSY/EPERM/EACCES can mean the running browser holds the store. Ask the user to completely exit that browser; warn that quitting may lose session cookies. SQLite BUSY/LOCKED on any platform also returns `locked`. Other read errors, Linux permission failures and worker timeout/crash return `unreadable`, which recommends Canvas login instead of closing browsers.
- Discovery marks the affected source unavailable for profile metadata or cookie-path read errors; unreadable Preferences use `Unavailable profile`, not a guessed default name. A Chromium Local State read failure marks all sources in that root unavailable, since names, keys and app-bound protection depend on it. Directory/Firefox index enumeration errors only produce a root placeholder (`profile: Unavailable profiles`, null count/expiry) when no sources could be found; otherwise each discovered profile is checked independently. Path-resolution errors retain their read reason; only a successfully resolved out-of-root path is `scope`. No paths or raw OS errors enter the result.
- `activeWorkers` still checks the **whole context**, not just the import site. Its reason lists up to five `tab-id origin` entries; same-origin tabs are listed for service workers, and a service worker with no same-origin page is listed as `service-worker origin`. Additional entries become `…`; paths and queries are omitted. Nothing closes automatically. Ask before closing tabs (forms may be unsaved), fetch fresh IDs with `tabs` after every restart, then retry. Import success alone is not proof of login: open a signed-in page and read it after completion.

## Skill CLI

See `skills/browser/SKILL.md`. Commands: `open`, `read`, `click`, `type`, `press`, `scroll`, `screenshot`, `tabs`, `select-tab`, `close-tab`, `handoff`, `signin-sources`, `signin-import`, redacted `status`, and one-shot `operation`. Uses `HALO_EXT_NODE` and the hook-1 environment map; no keys in arguments, URLs, logs or files. Errors never serialize Playwright/OS/fetch exceptions. Pending import output retains `id`, and completion notices include it. Keep that ID, end the turn, then retrieve once with `operation <id>` after completion and a new human reply for the import; no polling or mutation replay; the next action after a new human message returns control automatically.

Viewer imports browser DTOs directly; both halves import generic snapshot types relatively. Tests use manufactured local HTTP/profile fixtures only. No service restart, installed extension or browser binary is part of this source change. Viewer/package details are below.

Backend entry for E: `backend/src/index.ts` → `backend/index.cjs`; keep Playwright and ws external and ship their production dependencies beside the bundle, including Playwright's CLI and `playwright-core/browsers.json`. Ready/listen needs no browser install. F integration is a static `createSigninService` import passed as `signin` to `BrowserBackend`; no F-owned stub is present.

Acceptance here uses simulated Halo caller/notice IPC plus real local Chromium. First network download, packaged macOS/Windows installed-channel launch, current-user ACLs and native process cleanup are release gates, not claimed passing tests. Oversized JPEGs exceeding the fixed 512 KiB outbound budget are explicitly reported and dropped; the limiter never queues them. This preserves the protocol budget but does not promise streaming arbitrarily noisy pages.

## Canvas viewer

Requires **Halo 2.4.0** (generic backend hooks and file-less Canvas). Open from Settings → Extensions → Open in Canvas, or the agent's Browser notice. Backend confirmation is still required; installing does not enable the browser skill on every agent. This is a file-less Canvas view, not an activity page or a file preview; no filesystem, save or media grants are requested.

A single 32px toolbar contains back, forward, reload, editable address, new tab, status chip and an information popover. Enter navigates to an http/https URL (missing scheme defaults to https); other schemes, userinfo and search queries are rejected, never searched. New tab creates/selects a blank page and focuses the address. The tab strip appears only with two or more tabs, with selection and close buttons. Closing the last page through the viewer protocol creates/selects a replacement blank. The remaining area fits the unchanged 1280×800 page with letterboxing. The information popover holds limitations and closes on a second click, outside click or Escape; no footer or guidance row takes page space.

The chip shows agent driving, read-only watching, or you driving/agent paused, plus the backend's **2 fps** watch / **10 fps** user-control mode (0 means capture suspended, not a measured frame rate). Its title/accessible label explains that the agent can still view, and any chat reply allows agent actions again. Page pointerdown/keyboard, address Enter, navigation buttons and tab selection/close automatically request takeover before the first action; actions wait for `canInput` from the backend. Hover/wheel never request takeover, and wheel is not forwarded before a grant. When the backend revokes input, it releases held keys/buttons; the viewer clears local input state without sending a now-forbidden release. Only one viewer owns input; a competing request is rejected with “Another viewer is driving” and its queued actions are discarded. Finish by returning to the same Halo chat yourself and telling the agent what to do. There is no takeover/chat/Done button, `focus-chat` emission, automatic login detection, fabricated chat message or view-side resume command.

The viewer `navigate`, `back`, `forward`, `reload`, `new-tab` and `close-tab` frames share the input/select-tab ownership checks and workspace serial queue; navigate uses the agent open URL validator. Agent `close-tab <id>` uses the same close implementation, including a replacement blank for the last tab, and is fenced like other actions. Open/handoff notices are keyed by workspace/session/view, replaced on repeat and withdrawn when a viewer attaches (including a Settings viewer without session context); no new invitation is issued while a viewer is connected. Completion notices remain independent until their ordinary TTL/caller/backend lifetime ends because they carry the operation ID and terminal outcome. Canvas actions omit a title override so Halo can use manifest `title_zh`. Halo's notice `message` is a single string, with no localization map/key: viewer chrome is bilingual, backend notice text is not automatically localized by the host.

Binary JPEGs are decoded before ACK, fit without stretching, and mapped from viewer CSS pixels to the backend's 1280×800 CSS viewport independently of device DPI. Pointer capture handles drags outside the image; blur/cancellation releases held input. Keyboard events carry shortcuts/navigation; textarea composition and plain-text paste use the bounded text frame. File upload/download management, remote clipboard copy/cut, audio/video calls, passkeys and native permission dialogs are explicitly unsupported. Native OS IME, touch keyboards and hardware DPI still require device acceptance; fixture composition is not an OS keyboard test.

Tailwind CSS and JS are bundled locally with no CDN. The viewer applies the host's semantic palette and English/Chinese language frames. It accepts init/theme/lang only from its same-origin parent, and uses the frozen Canvas context for the proxy's header/query (routing metadata, not credentials). Hidden/page-exit closes the stream and clears the image; visibility restoration/remount resolves the view again. Transport loss uses bounded reconnect backoff, never state polling, and never silently retakes input ownership. The backend retains profile/lease state.

## Build and package

From the hub root, with Node ≥22.13, system `zip`/`unzip` and the pinned dependencies installed:

```sh
npm --prefix extensions/browser run typecheck
npm --prefix extensions/browser run test:viewer
npm --prefix extensions/browser run test:pack
npm --prefix extensions/browser run build
node scripts/pack.mjs extensions/browser
# dist/browser-1.0.0.zip + dist/browser-1.0.0.update.json
```

For a local directory-drop update, extract to a hidden sibling and atomically replace the installed `browser/` directory, rather than overwriting nested files: Halo's root watcher keys backend instances by version plus directory install time. It stops the old backend and starts the replacement on demand; the existing per-id backend confirmation survives when the directory never disappears from a scan. No Halo server restart is needed. For a same-version development replacement, hard-reload/reopen Canvas to avoid immutable asset caches.

`build.mjs` bundles the viewer to `dist/viewer.{js,css}` and backend to `backend/index.cjs`. Playwright, ws, tldts, D-Bus and their required production dependency closure remain external under `backend/node_modules/`, including the Playwright CLI/browser revision metadata and upstream licenses. Playwright's optional macOS `fsevents` watcher is not used by browser automation. No browser executable or real profile is included. Build uses disposable `.staging/build` and replaces only generated `dist`, `backend/index.cjs`, `backend/node_modules`, removing obsolete `backend/native` — **never `backend/src`**. Concurrent builds in the same worktree are not supported.

Browser uses ordinary single-package packing: build first, then `node scripts/pack.mjs extensions/browser` zips existing outputs without rebuilding. Neither browser build nor pack accepts a platform flag. `voice-input` and `htrans` retain their per-platform STT builder and ZIP behavior unchanged. Browser ZIP contents are allowlisted: manifest, HTML, icon, README, built `dist`, shipped skills, backend bundle and external modules. Browser source, tests/fixtures, build scripts, contract dev inputs and package lock/config are excluded. Dependency copying also removes known test/example/docs/fixture/benchmark/coverage and `.github` directories, `*.test.*` / `*.spec.*`, source maps and TypeScript (including `.d.ts`); runtime resources, `package.json` and licenses remain. Playwright's `lib/mcp/test/` is a precise exception: its CLI directly imports that runtime module on startup, so deleting it would break browser installation. The contract license is retained in `dist/halo-core-LICENSE`.

Compatibility follows the hub convention: **`minHalo: "2.4.0"` in generated update JSON**, not the manifest. Halo's update parser validates and enforces that field. Since this is unpublished, pack seeds that first value; after release the committed `extensions/browser/update.json` is authoritative and carried forward. The update uses only top-level `url` / `sha256`, with no platform `packages` map. Do not commit an unpublished download URL/checksum.

**Platform-independent runtime:** the same JS ZIP serves Linux, macOS and Windows; no Node executable, browser binary or compiled sign-in bridge is shipped. The bundle includes the sign-in JS/SQLite worker and external D-Bus dependency; `/usr/bin/security`, Windows PowerShell and a reachable supported Linux session bus are target OS prerequisites. Playwright's driver runs on Halo's Node, and pinned Chromium/ancillary browser downloads happen on the target in extension-data. Old `backend/native` outputs are removed and excluded. A portable package is not native hardware acceptance: first browser downloads, Mac/Windows OS prompts, installed-browser launch, ACLs, IME/DPI and process cleanup still require device testing before release.

Tests use a local fixture host against D's real backend and an independent Chromium viewer (DPR 2), with no live accounts. They cover rendering, mouse/key/composition/paste/wheel/drag/blur, 2→10→2, automatic takeover ordering for every control, second-viewer rejection without replay, URL restrictions, owner reads during user control, automatic action return after new human markers, ownerless claim, password-value masking across ordinary/nested iframes and open shadows, ARIA list/derived names, type/value changes and frame-collection errors, closed-shadow boundaries, 10k-item reads under three seconds, delayed key-up/in-flight viewer input ordering, viewer/agent last-tab replacement, keyed notice withdrawal, absence of focus-chat, hide/show/reconnect/remount and theme/language. Pack tests inspect ZIP/SHA-256, boot an extracted backend with no development dependencies and exercise production sign-in discovery/SQLite, validate Canvas rules, and run both STT builders through fixtures on all five platforms. Real pack builds use isolated fixture directories so backend, viewer, pack and sign-in suites can run together at default test concurrency. Real Halo Admin host integration, first browser download, native sign-in/IME/process cleanup and Mac/Windows acceptance remain release gates.
